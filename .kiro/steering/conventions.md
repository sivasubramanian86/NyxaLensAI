# NyxaLensAI — Coding & File Conventions

## Directory layout (do not restructure)

```
.kiro/
  steering/        ← project rules (this file lives here)
  specs/           ← one subfolder per phase, each with requirements/design/tasks
cdk/stacks/        ← single CDK stack: nyxalens_stack.py
lambdas/shared/    ← schemas.py, bedrock_client.py, github_client.py
lambdas/<name>/handler.py   ← one file per Lambda; entry point always lambda_handler
data/patterns_20.json        ← the pattern corpus — do not rename
data/patterns_20_embedded.json  ← generated by seed_opensearch.py --mode local
data/seed_opensearch.py      ← seeder script
docs/SCORING_RUBRIC.md       ← scoring + collision threshold docs
tests/unit/                  ← pytest, mocked boto3
tests/integration/           ← end-to-end tests against real or stubbed AWS
tests/fixtures/              ← 3 curated demo repos (pre-cached Dossier JSON)
frontend/                    ← Next.js 14 App Router
```

## Python style

- `ruff` enforced; line length 100; double quotes
- Type hints on all function signatures
- Pydantic v2 `.model_validate()` and `.model_dump()` (not `.parse_obj()` / `.dict()`)
- `@lru_cache(maxsize=1)` for any boto3 client or secret fetch at module level
- No `print()` in Lambda handlers — use `logging.getLogger(__name__)`

## Lambda conventions

- Entry point: `def lambda_handler(event: dict, context) -> dict`
- Never import `shared.*` with a relative path; the CDK asset bundle includes `shared/`
  as a sibling directory. Use `from shared.schemas import ...`
- Each handler validates its input with Pydantic before any AWS call
- Each handler writes atomic status updates to DynamoDB before returning

## Bedrock conventions

- `invoke_lite()` for: classification, keyword extraction, domain stripping
- `invoke_sonnet_json()` for: synthesis, Kill/Keep/Inject generation, Mermaid diff
- Never call `invoke_sonnet_json()` without a strict tool-use schema
- Always pass `system=` prompt when calling Sonnet for structured output

## Test conventions

- Unit tests mock all boto3 clients — never hit real AWS
- Use `pytest-mock` `mocker.patch` or `unittest.mock.patch`
- Test files named `test_<module>.py` inside `tests/unit/`
- Every new Lambda handler gets a corresponding unit test file

## Acceptance gate

A phase is complete only when **all of the following pass**:
1. `make lint` — zero ruff errors
2. `make test` — all unit tests green
3. All Acceptance Criteria in the phase's `tasks.md` checked off
